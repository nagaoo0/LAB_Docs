---
title: "vec3"
---

Positions, directions, offsets and colours: the one vector type a Lua script has, and the
operations on it. See [Lua Scripting](../../index.md).

## `vec3.new()`, `vec3.new(n)`, `vec3.new(x, y, z)`

```lua
local origin = vec3.new()
local uniform = vec3.new(2.5)
local direction = vec3.new(0, 0, -1)
```

Three constructors and no more: no arguments gives the zero vector `(0, 0, 0)`, one number gives
that component three times, and three numbers give each component its own. Two numbers is not a
form, and a call written that way is a Lua error rather than a guess at the missing component.

Almost everything in the rest of the manual takes or answers one: positions, velocities,
directions, scales, colours and emissive tints are all `vec3`s.

## `v.x`, `v.y`, `v.z`

```lua
local p = vec3.new(1, 2, 3)
p.y = p.y + 1
log.info(tostring(p.y))
```

Read and write, as plain numbers rather than accessor calls. Writing one changes that vector
alone: two vectors holding the same components share nothing between them, so a copy is built by
hand, `vec3.new(v.x, v.y, v.z)`.

## Operators

```lua
local a = vec3.new(1, 2, 3)
local b = vec3.new(4, 5, 6)

local sum = a + b
local difference = a - b
local opposite = -a
local scaled = a * 2
local scaled_too = 2 * a
local componentwise = a * b
```

`+` and `-` work component by component, unary `-` flips every component, and `*` accepts a number
on either side (a scale) or another vec3 (component-wise: `a.x * b.x`, `a.y * b.y`, `a.z * b.z`).

`tostring(v)` gives `vec3(` followed by the three components, six decimals deep, separated by
commas: `vec3(1.000000, 2.000000, 3.000000)`. That is what to use when a vector has to go into a
log line or a concatenation.

Two things are deliberately absent. There is no `/`, so scale by the reciprocal instead
(`a * 0.5`). And there is no equality operator: `==` compares the two Lua values, not the numbers
inside them, so two separately built vectors holding the same components are never equal. Compare
what is inside them, or compare with a tolerance:

```lua
if a.x == b.x and a.y == b.y and a.z == b.z then
    log.info("identical")
end

if (a - b):length() < 0.001 then
    log.info("close enough")
end
```

## `v:length()`

The magnitude: `vec3.new(3, 4, 0):length()` is `5`, and the zero vector is `0`. It answers a
number, so it composes with the rest of the arithmetic, which is what makes a speed test read
`entity:get_velocity():length()`.

## `v:normalized()`

The unit vector in the same direction: what a direction taken from two positions wants before
anything is moved along it.

**A zero-length vector answers `(0, 0, 0)`**, not a vector of NaNs. A direction that could not be
computed is therefore testable, `v:length() == 0`, rather than something that poisons every value
downstream of it.

## `a:dot(b)`

The sum of the component products. Between two unit vectors it is the cosine of the angle between
them, which is the cheap test for facing: greater than zero is in front, less than zero is behind,
zero is square on. `a:dot(a)` is the squared length, cheaper than `length()` when only a
comparison is wanted.

## `a:cross(b)`

The vector at right angles to both, following the right-handed rule the engine's axes use: world Z
cross world X gives world Y, so `vec3.new(0, 0, 1):cross(vec3.new(1, 0, 0))` is
`vec3.new(0, 1, 0)`.

The result is not normalised: its length is `len(a) * len(b) * sin(angle)`, so it is a unit vector
only when both inputs are unit length and perpendicular, and it shrinks toward the zero vector as
the two inputs line up.

The native module ABI has no vector maths, only the plain `LAB_Vec3` struct values cross in (see
[Transform](../../../03-cpp/api/entity/02-transform.md)); a module does its own.
